System Architecture

Core Tech Stack

01

Attendo is built using the Tauri framework, bypassing Electron to deliver a hyper-optimized, lightweight, and incredibly secure desktop application.

Frontend (UI Layer)

  • React 18 (TypeScript) for component logic.
  • Tailwind CSS for rapid, utility-first styling.
  • Vite for lightning-fast HMR and bundling.
  • Lucide React for optimized SVG iconography.

Backend (OS Layer)

  • Rust (Tauri Core) handles OS-level APIs and file access.
  • WebView2 (Windows) renders the React frontend.
  • Tauri SQL Plugin interfaces with the local database.

Codebase Structure

Data Layer

SQLite Schema & File System

02

Attendo is a 100% offline-first application. All data is stored locally in an SQLite database located in the Windows AppData/Roaming/com.attendo.app directory. This protects student data during app updates or uninstalls.

Table: students

CREATE TABLE IF NOT EXISTS students ( id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL, national_id TEXT UNIQUE NOT NULL, grade TEXT NOT NULL, qr_payload TEXT UNIQUE NOT NULL, is_deleted BOOLEAN DEFAULT 0 )

Stores the active and archived roster. Soft deletion is utilized (is_deleted) to preserve historical attendance data.

Table: attendance

CREATE TABLE IF NOT EXISTS attendance ( id INTEGER PRIMARY KEY AUTOINCREMENT, student_national_id TEXT NOT NULL, workspace TEXT NOT NULL, timestamp DATETIME DEFAULT CURRENT_TIMESTAMP, FOREIGN KEY (student_national_id) REFERENCES students(national_id) )

The immutable ledger of student scans. Data from here feeds directly into the Master Report and Analytics engines.

Table: settings

CREATE TABLE IF NOT EXISTS settings ( key TEXT PRIMARY KEY, value TEXT NOT NULL )

Stores global configuration (Instructor Name, University, Semester Dates) loaded during the Setup Wizard.

Security & Deployment

Licensing & Compilation

03

License Verification (JWT + HMAC)

Attendo uses stateless JWTs (JSON Web Tokens) signed with an HMAC SHA-256 algorithm. The Attendo_KeyGen.html acts as the master private keyholder. It embeds the machine's Hardware ID and Expiration Date into a Base64 payload, signs it with SECRET_KEY, and produces the token. Tauri strictly validates this signature and matches the Hardware ID locally via Windows WMI queries.

The 21-Day Offline Lock

To prevent indefinite license spoofing via system clock manipulation, Attendo integrates with Supabase. It must ping the server once every 21 days to log an online timestamp in localStorage. If the timestamp exceeds 21 days, the UI locks until internet is restored.

Build Pipeline

To compile a new production release of Attendo:

  1. Update version in src-tauri/tauri.conf.json
  2. Update version UI badge in src/App.tsx
  3. Run npx tauri build in terminal
  4. Retrieve the .msi and -setup.exe files from src-tauri/target/release/bundle/
